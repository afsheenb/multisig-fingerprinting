## Measured acquisition efficiency
- Phase 1 benchmark (21 consecutive recent blocks, heights 971989..972009, 1 pt each): 159,562 inputs examined, 7,208 multisig-bearing inputs, i.e. ~343.24 multisig-bearing inputs per point (~343 multisig-bearing inputs per block).
- Pilot scan (this corpus): 180 in-study blocks + 1 smoke-test block, 75707 distinct revealed scripts and 161202 spend observations, at ~1 point per raw block: 290.07 distinct revealed scripts per point. Not directly comparable with the benchmark number (a deduplicated script count versus multisig-bearing input observations); the pilot rate is pulled down by stratified sampling across the whole period, where 2023-era blocks carry far fewer multisig spends than recent ones.

## Full-period coverage extrapolation
- Study period: heights 812688..972009 = 159,322 blocks at exactly 1 point per raw block = ~159,322 points, about 160 UTC days at the 1000 point/day budget.
- The per-block input and multisig-bearing rates from the benchmark are upper bounds (recent blocks are larger); the point cost per block is exact and does not degrade.

## The indexed-access gap
- The indexed arm (/bitcoin/outputs, /bitcoin/dashboards) is unavailable on the no-key tier: every attempt received HTTP 430 (4 index/dashboard attempts, evidence in docs/api_notes.md); benchmark.json carries approach_b: null.
- Consequence 1: raw-block decoding is the only script extraction path (it is sufficient: raw blocks carry full witness data, but cost 1 point per block regardless of content).
- Consequence 2: deposit-side script visibility and case-2 key/scriptPubKey reuse remain unobservable without index access or prevout resolution; /bitcoin/raw/transaction is also soft-blocked (empty 200s), which is why validation runs locally against cached prevouts only.
- If paid/key-tier index access is ever authorized, the first check is whether indexed outputs carry full spending witness stacks (the spending_witness question, docs/api_notes.md).
